How many are nonstandard?

Fourteen are Midnight-specific. Another six use Mistral voice semantics: 20 operations outside the working OpenAI-compatible subset. Routes shared by dialects are counted once. A familiar URL does not guarantee identical behavior.

One listener. One loaded model.

All calls use the same host and port. An OpenAI SDK uses the base URL http://127.0.0.1:8080/v1; native clients append the full paths below to http://127.0.0.1:8080. Replace the example port with your listener port. API-key authentication is optional. With MIDNIGHT_API_KEY unset, the listener starts without a key and accepts requests without Authorization. To enable authentication, generate a random 256-bit key with midnight api-key generate and set MIDNIGHT_API_KEY before startup; every route then requires Authorization: Bearer KEY. Missing or incorrect client keys return HTTP 401 only when authentication is configured. Invalid or empty server keys still prevent startup. To disable authentication, unset the variable and restart. The examples below assume no configured key; add the bearer header when authentication is enabled. HTTP does not encrypt the key; use TLS termination for remote clients.

The runtime owns one loaded selection per server process. Inspection and generation lease that same selection. Switching drains active work, releases the old backend and cleans up unused memory before loading its replacement. Discovery lists preflight-valid installed checkpoints and marks the ready resident selection with loaded:true. Named inference requests automatically wait for and load their catalog selection; discovery itself never loads weights. Stored response history and retained recording sessions belong to the listener and can survive model unload.

Model information and runtime measurements

Studio opens a separate Model Information screen with m; i returns to layers and Esc returns to the previous screen. It combines GET /v1/inspector/model architecture discovery with GET /v1/runtime allocator and serving data. Both are Midnight-specific, read-only operations using the listener’s optional authentication. Runtime data refreshes every two seconds while this screen is visible. Architecture is reused only for the same resident modelGeneration; mismatched model IDs or generations are rejected.

Runtime state adds optional generationMetrics: tokensPerSecond for emitted decode tokens, promptTokensPerSecond for evaluated prefill tokens, promptTokenCount, prefilledPromptTokenCount, cachedPromptTokenCount, generationTokenCount, and stopReason, plus optional existing draft acceptance fields. This is the latest text backend completion report, including headless serving, rather than a live speed stream or an average across requests. It is absent before the current loaded model’s first report, for non-text backends, when rates are invalid, and during unload/replacement. Reading it does not enable per-token monitoring.

The screen distinguishes stored tensor bytes, memory.activeBytes, memory.cachedBytes, memory.peakBytes, and the resident model’s memory_limit_bytes budget. Allocator figures exclude other process/system allocations; Apple Silicon uses unified memory. Dedicated VRAM capacity and total system GPU usage are not supplied by these fields. Architecture details include actual layer layout, hidden width, attention/KV heads, experts per token, activation, context limits, and quantization formats/group sizes reported by the loaded graph. Missing or unsupported data is labelled Not reported; older/direct servers may lack runtime measurements. Opening this screen performs no inference or model mutation.

Existing URLs and response contracts are preserved. Runtime, inspector, audio, vision and Responses handlers are separated internally, sharing the listener rather than creating additional servers.

Midnight routing · 20 September 2026

Request a model. Midnight loads it.

On the existing OpenAI-compatible discovery routes, installed models remain listed while unloaded. The Midnight-specific boolean loaded is true only for the ready resident selection. Unloaded entries expose preflight metadata rather than measured runtime properties; created:0 means no runtime creation timestamp. Capability metadata describes the configured backend, not whether its weights are currently resident.

Set an exact catalog ID in model on POST /v1/chat/completions, POST /v1/responses, or POST /v1/audio/speech (OpenAI or Mistral-style). Midnight waits for admitted work to finish, releases the previous backend, loads the requested selection and serves the request with a lease on that exact model. It never substitutes another model. Requests without an explicit model retain the existing current-model behavior. Inspection and voice discovery without a model selector do not trigger loading.

Cold loads add latency

Only one model is resident. Same-model requests can run concurrently after admission; different-model admissions are serialized FIFO, with up to 64 waiting admissions. Overflow and conflicting manual mutations return 409 model_transition_in_progress. Unknown IDs return 404 model_not_found; failed loading returns 503 model_load_failed. Cancellation removes queued admissions but does not interrupt an already-started shared load. Clients must allow loading plus inference time in their timeout. No multi-model warm pool, force-cancel, target-model download or inference-supplied filesystem path is supported. Named speculative assistants can download during a load as described below.

The catalog scans immediate model directories under MODEL_RUNNER_MODELS_DIR (default ~/.midnight/models), the launch checkout’s Models/, and optional colon-separated MIDNIGHT_MODEL_DIRS. Invalid preflight entries and ambiguous duplicate IDs are omitted; configure unique servedModelName settings. Explicitly loaded aliases and their settings are remembered for the process lifetime and revalidated. Preflight reads metadata only and cannot guarantee that tensors load or fit in memory. Existing route counts remain unchanged.

02 · Midnight-specific / nonstandard OpenAI

Control and inspect.

Reset KV caches

POST /v1/runtime/reset-cache with {} returns {"reset":true} after clearing retained text-model KV caches, including shared prefixes and conversation checkpoints. Midnight-specific; managed listener, loaded text model, loopback JSON clients only. Serializes with generation and keeps model weights, stored Responses records, and client history. Other clients sharing this model also lose cache reuse. Subsequent requests rebuild caches from their history; this does not erase conversational context. Unsupported models or invalid bodies return 400, remote/browser-origin requests 403, full execution queue 409, and an unavailable model 503. It does not unload the model.

These are existing Midnight extensions. You can use standard chat without calling them. Load/unload is asynchronous; a 202 response means accepted, not ready.

Midnight Activation Capture

Midnight exposes selected residual activations as a public runtime feature. Any HTTP client permitted by the listener’s configuration can use the same discovery and capture contract for distillation research, evaluation, or representation analysis. ABSlayer and midnight-moonshine are consumers; no ABSlayer package or job controller is required. Dedicated capture and external chat recording operations are Midnight-specific, using the listener’s optional bearer authentication.

OperationConsumer contract
GET /v1/inspector/modelDiscover id, runtimeGeneration, traceSupported, available layers, and traceCapabilities. Capability version 1 advertises sites, hidden widths, capture modes, encoding and limits.
POST /v1/inspector/traceSend the discovered model ID and generation, a question, explicit layers and token positions, and capture: raw or both. The default summary mode does not return raw vectors.
Returned tensorsBase64 little-endian float32, shaped [selectedTokenCount, hiddenWidth], with layer/site identity, absolute token indices and token IDs. Validate shape, byte count, row identity and finite values before use.

Discover, select, capture

BASE="${MIDNIGHT_BASE_URL:-http://127.0.0.1:8080}"
curl --fail-with-body -sS \
  "$BASE/v1/inspector/model" > model-capabilities.json || exit 1

# Abort if the loaded model does not advertise raw activation capture.
jq -e '.traceSupported == true and (.traceCapabilities.captureModes | index("raw") != null)' \
  model-capabilities.json > /dev/null || exit 1

jq '{model: .id, runtimeGeneration: .runtimeGeneration,
     question: "Explain how a cache hit differs from a cache miss.",
     maxTokens: 0, layers: [.layers[0].index], sites: ["layer_input"],
     tokenPositions: {prefill: [-1], decode: []},
     capture: "raw", maxCaptureBytes: 1048576}' model-capabilities.json |
  curl --fail-with-body -sS \
    -H 'Content-Type: application/json' --data-binary @- \
    "$BASE/v1/inspector/trace" > activation-capture.json

Uses an already loaded model without a configured server key. Add the bearer header when authentication is enabled. The two JSON files are written by this example client. Record the source checkpoint revision and weight hashes separately; runtimeGeneration is an instance guard, not a portable checkpoint fingerprint.

Capture scope and current limits

Native Laguna, Mistral3/Ministral3 and GPT-OSS runtimes currently advertise capture when their module geometry is supported. Other architectures, including Gemma through this HTTP API, may expose metadata without raw capture; discover support first. Sites are layer_input and after_attention residuals, not attention probabilities or arbitrary intermediate tensors. Dedicated trace limits are 256 rendered prompt tokens, 0–64 generated tokens, 1–128 explicitly selected available layers and at most 16 MiB of estimated capture payload. External chat recording uses the separate bounds below.

Negative prefill positions count from the end of the rendered prompt, including template tokens. Decode positions are emitted-token ordinals. Early EOS can leave requested decode positions unobserved; the report identifies them. Dedicated traces use a fresh KV cache and serialize with ordinary generation. Midnight restores the original modules on completion, failure or cancellation.

This is a bounded JSON operation, not a streaming or bulk activation dataset service. Captures do not identify isolated domain knowledge, train a student or modify model weights. Consumers own those analyses, training runs and artifact storage.

Record a conversation. Replay its activations.

Arm POST /v1/inspector/recordings, then chat through OnoSendai or another client connected to this Midnight listener. The next admitted ordinary Chat Completions or Responses generation on the loaded runtime claims the recording. Studio needs no prompt field and Midnight generates no second answer. Recording is not bound to a particular client or conversation ID.

  "$BASE/v1/inspector/recordings/$RECORDING_ID"

Reuses BASE and model-capabilities.json from discovery above. POST returns 202 with the armed session; GET and DELETE return 200 with session state. All three calls follow the listener’s optional authentication setting.

Recording captures the final evaluated prompt token and at most the first selected number of emitted tokens. Its trace has outputKind: "recorded", an empty question, and answer for the recorded generated window. The tokens array contains only the observed window. Token positions and sample tokenIndex values are absolute: final prompt at promptTokenCount - 1, first emitted token at promptTokenCount. Full-request prompt/generated counts can exceed the saved token count. Cached prefixes are not recomputed, and no full prompt, full transcript, raw vectors or logits are retained.

Token labels plus the recorded answer have a separate 64 KiB decoded-text budget; exceeding it fails the recording without truncating content or interrupting chat. The request’s sampling, parser and response limit remain its normal settings. Speculative decoding and Laguna compiled block tails are disabled for that captured request to observe ordinary target forwards. Summary collection adds runtime cost. Unarmed generation installs no recording wrappers or reductions. Recording completes when the chat request finishes; polling is not a live activation stream.

Save recordings in the client

The server keeps at most four recent sessions in memory, with one armed or active recording at a time. Starting another session evicts the oldest when full; a process restart clears all sessions. Unloading or replacing the model cancels a recording that is still armed. GET and DELETE remain available during generation and after model unload. DELETE stops collection without cancelling chat; a completed capture remains available. Studio saves recordings/<UUID>.json with the capture and original model topology, plus recordings.jsonl event history under --state-directory (default ~/.midnight/studio/). New directories use mode 0700 and files 0600. Artifacts contain recorded token text, including the final prompt token, and the bounded answer window. They omit endpoint/authentication values and do not save the full prompt. In the layer view, a arms/stops Record; Space plays/pauses, Left/Right steps tokens, v cycles component/residual views, and l opens the saved library. Library replay requires no model call.

Unknown or evicted IDs return 404 recording_not_found; a second armed/active recording returns 409 recording_busy. Invalid selection returns 400 invalid_inspector_request; requests over 32 KiB return 413. Unsupported native runtimes return 422 unsupported_model_feature; non-text backends return 501. Unavailable or changed model instances follow the existing 503/409 lifecycle errors. The ID must be a UUID; recording routes accept no query parameters.

Passive recordings add optional components and expertRouting fields in the trace. Component entries use index, actual projection path, site and residual-style samples; sites are attention_output, dense feed_forward_output, and shared_expert_output where present. These are actual original projection outputs before residual addition, including quantized modules. Discovery lists available kinds in traceCapabilities.recordingComponents; dedicated /trace raw sites remain unchanged. Expert entries contain index, router path, expertCount, and samples with tokenIndex, selected expertIDs and corresponding normalized weights. Laguna observes router results; GPT-OSS mirrors the pinned router selection on actual projection output. Bounds are 4096 experts and 64 selections per token. Unsupported geometry fails recording while chat continues. Routed expert output vectors and the combined GPT-OSS MoE output are not captured.

Studio capacity bars still represent stored weight size. Attention and dense/shared feed-forward bars use their own output RMS with fixed recording-wide scales per kind. Router/norm/unmeasured capacity stays dim. Separate expert ID tiles identify actual selected experts and print routing weights; their size does not represent stored bytes. Unlisted routed experts were not selected. Older recordings explicitly retain whole-layer residual brightness. Individual weight elements, neurons and causal importance are not measured. Saved JSON preserves component and router fields for offline replay. Durable logs and downstream analysis belong to clients.

Local control contract

Load, unload, downloads and remove require a loopback client, Content-Type: application/json (including GET downloads), and no Origin header or cross-site browser request. Use a native client or terminal. remove deletes files; unload only releases RAM.

Midnight model-card extension · 20 September 2026

Find voices before loading.

GET /v1/models and GET /v1/models/{id} expose model_card.voices for speech models. Each choice contains id, readable slug, name, languages, optional gender, and requires_reference_audio. Use its ID or slug as OpenAI voice or Mistral-style voice_id. Voxtral IDs are stable UUIDs; Qwen and VibeVoice use their selection names.

Unloaded choices come from checkpoint metadata and available local presets without allocating weights. The loaded synthesizer supplies the authoritative catalog. Editable card files cannot override it. Missing voices means unknown/not applicable; an empty array means no available selections. Languages describe the current Midnight routing.

Cloning is a selection, not a saved voice

A choice with requires_reference_audio:true needs Mistral-style ref_audio. Qwen Base additionally requires ref_text; VibeVoice does not. Persistent custom-voice creation remains unsupported. Mistral-style GET /v1/audio/voices continues to list only the currently loaded model’s voice resources.

The voice array is a Midnight-specific extension on existing OpenAI-compatible discovery responses and runtime model cards. No new route is introduced.

Speech backend · 19 September 2026

VibeVoice 1.5B and community 7B.

The converted official 1.5B checkpoint and pinned community Transformers 7B checkpoint are served by Midnight through a persistent local PyTorch MPS/CPU worker. The 7B mirror is vibevoice/VibeVoice-7B-hf at revision aae5684b9755da90bb1c75417a9bca4454dab418; it is not an official Microsoft redistribution. Its downloaded LFS hashes are verified. MPS loads 7B in BF16 directly on device; 1.5B and CPU use Float32. Only one selection is resident per listener. OpenAI-compatible POST /v1/audio/speech accepts voice selections default, female, male, and cheerful-female. Reference presets depend on local sample availability; discover the current catalog.

Mistral-style speech on the same route accepts voice_id:"clone" and base64 ref_audio; VibeVoice does not require ref_text. Do not mix OpenAI and Mistral fields. References must be finite mono 24-kHz audio, 1–30 seconds and at most 8 MiB decoded. They remain in memory; no URL fetch or persistent custom voice is created. The clone catalog entry is a request-time selector requiring reference audio.

Explicit local limits

Set response_format to wav or pcm; default MP3 is unsupported. Output is mono 24 kHz: OpenAI uses PCM16, Mistral float32. Speed must be 1. Instructions, multi-speaker scripts, transcription and stored voice creation are unsupported. Synthesis buffers the full utterance before returning audio, including Mistral SSE; it is not incremental synthesis. Maximum input is 4096 characters; output ceiling is at most 4096 tokens (launch default 512). Each worker exchange times out after 180 seconds. Cancellation or timeout terminates the affected worker; the next request starts a fresh worker, and unload waits for the exchange to drain. Token-ceiling outputs fail instead of returning truncated speech.

Midnight-specific CLI/model loading selects a converted model_type:"vibevoice" directory. Runtime setup is required before loading; weights are local-only during inference. Model discovery advertises reference-audio input and speech output. Existing route inventory was 23 before the cache-reset extension operations.

  -H 'Content-Type: application/json' \

  -H 'Content-Type: application/json' -d '{}'

  -H 'Content-Type: application/json'

Load a supported voice model first. Text models do not gain speech capability merely because the route exists.

05 · Client notes

Details that matter.

Client generation settings

Lowlight, Highlight and Lowlight Relay save temperature (0–2) and top_p (greater than 0, up to 1) per endpoint and model. These are OpenAI-compatible request fields on Chat Completions and Responses, not new Midnight routes. Terminal clients use /set temperature 0.7, /set top-p 0.95 and /set sampling default. Highlight exposes Generation fields in connection settings. Clearing an override omits that field; Midnight currently uses temperature 1.0 when omitted, not an automatically selected author preset. Other servers may use different defaults. Settings affect subsequent requests and do not change model weights. Existing maximum-output controls remain available. Top-k, min-p, seed, logprobs, n, and repetition, presence, or frequency penalties are not accepted. Chat Completions rejects unknown or misspelled top-level fields. Gemma assistants support target-verified sampling at nonzero temperatures.

Lowlight, lowlight-relay and highlight

These clients discover models with GET /v1/models. They read optional model_card.name and model_card.description. Model pickers show the common name with the routing ID available; missing or malformed cards fall back to the ID. Selection and generation always use id, never the common name. Lowlight refreshes on reconnect; highlight has a Refresh action. After editing a folder's card, reload that model in Midnight, then refresh the client. This is metadata for the currently advertised model, not a listing of all cards on disk.

ID ≠ display name

  • Stored responses: defaults to enabled; in-memory only, up to 128 responses / 64 MiB / one hour. Restart clears history. store:false disables storage for that result.
  • Streaming: Chat uses SSE chunks and [DONE]. Responses uses typed events. Disconnect cancels the active request; there is no response-cancel-by-ID endpoint.
  • Inspection: discover capabilities before tracing. A minimal prefill request includes question, maxTokens:0, layers:[0], and tokenPositions:{prefill:[-1],decode:[]}. Send the discovered model ID and runtimeGeneration to reject a stale selection.

  • Errors: 400 invalid request/limits; 403 local-control restriction; 404 missing model/response; 409 busy or stale selection; 422/501 unsupported feature. Inspect the returned error code.
  • Connection: examples assume local loopback. When a server key is configured, every route requires its bearer value and placeholders return HTTP 401. Midnight-specific speculative decoding · 22 September 2026

Laguna: smaller blocks, explicit opt-in.

When a Laguna DFlash checkpoint is explicitly configured, omitted dflashBlockSize now means 3, capped by the checkpoint maximum, instead of using its maximum of 16. Explicit block sizes still override the default. Muse retains its default of 4. These are Midnight-specific load settings; OpenAI-compatible and Mistral-style route classifications and the route inventory are unchanged by this feature. Laguna is still excluded from automatic assistant discovery.

Fresh paired Metal measurements on the installed Q4R8 Laguna target found the old block-16 path 56.6% slower than its target-only control; the rebuilt default-3 path was 6.7% slower on the same 256-token tutorial. No general speed win is established. CUDA has not been revalidated. Small blocks reduce rejected verification work, but do not guarantee identical output.

Fixed-prefix diagnostics found exactly identical logits with and without DFlash hidden-state capture. Ordinary batched target forwards, even without any drafter or rejection rollback, can change the winning token at low-precision ties. The full DFlash comparison reproduced that divergence. Exact target-only equivalence remains unproven; new DFlash A/B reports use failed_output_parity when it fails. Higher-precision diagnostics and a separately quantized drafter have not been promoted to production workarounds. Laguna DFlash now participates at nonzero temperatures, including the default temperature 1.0. It proposes greedy tokens without consuming sampling randomness; the target samples every emitted position using the existing OpenAI-compatible temperature and top_p fields and accepts only matching draft prefixes. This replaces the earlier greedy-only fallback. Higher sampling entropy can lower acceptance and speed. Muse’s separate greedy-only restriction is unchanged; structured-output, forced-tool and native-protocol requests retain their existing target-only routing.

The follow-up corrected the benchmark control to retain ordinary target decoding’s production optimizations. Earlier percentages used a control with those optimizations disabled. Across a small three-prompt Metal screen, block-3 DFlash ranged from about 13% slower to 3.5% faster; shared-machine drift prevents a general speed claim. A developer-only compiled verification experiment preserved logits and captured features in the measured diagnostic but showed no consistent speed benefit and remains off by default. No HTTP fields or routes changed.

Midnight-specific · Decision models

Typed decisions with candidate probabilities.

POST /v1/decisions accepts model, context, and a nonempty schema object. Each field has type (boolean or enum), a description, optional choices and choice_descriptions. Enum choices are distinct strings; boolean choices default to false then true. Optional field_order lists each field once; otherwise JSON schema order is preserved. Optional score_fields names integer-valued enum rubrics.

The response includes typed output, per-field value, candidate probabilities and logits, optional expected_score, model/source revision, artifact hash, applied temperature, and total prompt tokens across independent field passes. The runtime reads next-token candidate scores and constructs the output directly.

Limits: text only, flat fields, at most 128 fields and a 64 KiB request. Choice and context limits come from the pinned model contract (latest Nimble: 255 choices and 8,192 tokens per complete field prompt). Oversized prompts are rejected, never truncated. Nested objects, free-text extraction, explanations, streaming, dependent fields and automatic cross-field consistency are unsupported. Candidate probabilities are not a guarantee of correctness.

Discovery exposes model_card.capabilities.decisions when a loaded model carries a validated decision contract. Unsupported models return 422; malformed requests return 400; busy execution returns 409. Authentication and managed-model leases match the existing serving routes.

Model development lives in Afterglow: native training, calibration, conversion, quantization and export. midnight download nimble-9b downloads the official pinned base and LoRA source bundle; afterglow convert prepares it for serving. Real-model validation evidence is tracked separately from download availability.

Runtime compatibility

Gemma nested tool arguments

OpenAI-compatible chat and Responses tool calls preserve nested objects and arrays when Gemma emits marker-delimited strings inside them. For example, a filter containing an array of extensions and a boolean reaches function.arguments as JSON with an object, array and boolean, rather than a string containing Gemma protocol markers. The correction applies to the reviewed native Gemma parser and adds no request field, response field or route.

Limits: complete marker-delimited string spans are decoded literally, preserving quotes, backslashes and punctuation. Bare unquoted values are not guessed into strings. Malformed or incomplete nested spans are not promoted into valid structured data; whole escaped object-shaped string parameters remain strings. Tool calls still require client-side execution, and this parser correction does not guarantee that a model selects the correct tool or arguments. Model evaluations must identify the serving build.
